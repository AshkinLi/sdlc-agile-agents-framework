# Universal SDLC + Agile + Multi-Agent Development Framework

## 1. Purpose
This repository provides a standard framework for software development. The framework integrates the Software Development Life Cycle (SDLC), Agile methodologies, and autonomous AI Agents. You can use this framework for web, mobile, backend, embedded, or desktop software projects.

## 3. Quick Start: Automated Project Initialization
Run either entry point. `bootstrap.sh` is a thin wrapper that forwards every
argument to `bootstrap.py`, which is why Python 3 is required in both cases.

### Option A: Interactive Setup
Run the script without flags and follow the prompts:
```bash
./bootstrap.sh
# OR
python3 bootstrap.py
```

### Option B: Non-Interactive CLI Setup
Pass project parameters directly via command-line arguments:
```bash
./bootstrap.sh \
  --target /path/to/my-project \
  --name "Payment-Gateway-Service" \
  --type "Backend API" \
  --lang "Kotlin 2.0 / Spring Boot" \
  --build "./gradlew assemble" \
  --test "./gradlew test" \
  --lint "./gradlew ktlintCheck"
```

Or call the Python CLI directly (identical behavior):
```bash
python3 bootstrap.py \
  --target /path/to/my-project \
  --name "Payment-Gateway-Service" \
  --type "Backend API" \
  --lang "Kotlin 2.0 / Spring Boot" \
  --build "./gradlew assemble" \
  --test "./gradlew test" \
  --lint "./gradlew ktlintCheck"
```

## 4. Generated Target Project Layout
The bootstrap creates the following structure in the target directory:

```text
<target>/
├── AGENTS.md
├── README.md
├── docs/
│   ├── PRD.md
│   ├── ARCHITECTURE.md
│   ├── BACKLOG.md
│   ├── TEST-PLAN.md
│   ├── adr/ADR-001-initial-architecture.md
│   └── sprints/sprint-1.md
└── .agents/
    ├── roles/<role>/AGENTS.md
    ├── skills/<skill>/SKILL.md
    ├── architecture/*.md
    └── templates/*.md
```

The bootstrap guarantees the following:
1. **Single definition root**: every framework definition file is consolidated under `.agents/`; no top-level `agents/`, `skills/`, `architecture/`, or `templates/` directory is created.
2. **Consistent references**: every copied Markdown file is rewritten from the source paths to the generated layout (`agents/` -> `.agents/roles/`, `skills/` -> `.agents/skills/`, `architecture/` -> `.agents/architecture/`, `templates/` -> `.agents/templates/`), so references stay valid relative to the project root.
3. **Root entry point**: `AGENTS.md` remains at the project root for automatic agent discovery and gains a `Framework Location` line in Section 2.
4. **Generated project README**: `README.md` is rendered with the project context and the actual `.agents/` layout.
5. **Safe docs initialization**: existing `docs/` artifacts are preserved unless `--force` is passed; `AGENTS.md` is always regenerated from the framework template.
